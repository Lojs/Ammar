## 💡 الفكرة

أي شخص يبني بيته أو يشرف على مشروع إنشائي يوصل وضع يضيع فيه بين فواتير المقاولين والموردين. **عَمار** يحل هالمشكلة: تسجّل فيه كل قسم من مشروعك، وكل بند، وكل دفعة سويتها مع صورة الفاتورة نفسها — والتطبيق ياخذ لك الحسبة أوتوماتيكي.

## ✨ المميزات

- 🏗️ عدد لا نهائي من المشاريع، كل واحد مستقل تمامًا وبعملته الخاصة.
- 📂 هيكلة ثلاثية: أقسام ← بنود ← دفعات، مع حساب تلقائي للإجماليات والمتبقي.
- 📸 رفع صور الفواتير من الكاميرا أو الاستديو مباشرة.
- 📄 تصدير تقارير PDF منسّقة، وملفات Excel (CSV) احترافية.
- 💾 نسخ احتياطي محلي (ZIP) وسحابي اختياري (متوافق مع أي خدمة S3).
- 👥 تعدد مستخدمين مع عزل كامل للبيانات، ولوحة تحكم للأدمن.
- 🌓 وضع فاتح/داكن/حسب النظام.
- 🔒 مبني وتم تدقيقه أمنيًا (راجع [CHANGELOG.md](./CHANGELOG.md)).
- 🐳 تشغيل بأمر واحد داخل Docker — يدعم x86_64 وARM (بما فيها Raspberry Pi).

## 📋 المتطلبات

- Docker و Docker Compose مثبتان على الجهاز.

## 🚀 التشغيل بسحب الصورة الجاهزة (الأسهل)

ما تحتاج تحمّل كود المشروع إطلاقًا — فقط اسحب الصورة الجاهزة من GitHub Container Registry:

1. أنشئ مجلد فاضي بجهازك، وحط فيه ملف [`docker-compose.ghcr.yml`](./docker-compose.ghcr.yml) من هذا المستودع.
2. أنشئ بجنبه ملف `.env` (انسخ محتوى [`.env.example`](./.env.example)) وعدّل `JWT_SECRET` إذا حبيت.
3. شغّل:

   ```bash
   docker compose -f docker-compose.ghcr.yml up -d
   ```

5. افتح المتصفح على `http://localhost:8080`.

> 💡 صورة Docker تُبنى وتُنشر تلقائيًا مع كل تحديث بالمستودع (عبر GitHub Actions) — راجع [`.github/workflows/docker-publish.yml`](./.github/workflows/docker-publish.yml).

## 🛠️ التشغيل من الكود المصدري

1. انسخ المستودع:

   ```bash
   git clone https://github.com/lojs/ammar.git
   cd ammar
   ```

2. انسخ ملف الإعدادات النموذجي وعدّله عند الحاجة:

   ```bash
   cp .env.example .env
   ```

   على الأقل غيّر قيمة `JWT_SECRET` إلى نص عشوائي طويل وسري (أو اتركه فارغًا وسيُولَّد سر عشوائي آمن تلقائيًا).

3. شغّل التطبيق:

   ```bash
   docker compose up -d --build
   ```

4. افتح المتصفح على `http://localhost:8080`.

   أول مرة تفتح فيها التطبيق، ستظهر شاشة "إنشاء الحساب الأول". الحساب الذي تنشئه هنا يصبح تلقائيًا حساب أدمن.

5. لإيقاف التطبيق:

   ```bash
   docker compose down
   ```

   بياناتك محفوظة في مجلد `./data` على جهازك، وتبقى موجودة حتى بعد الإيقاف والتشغيل من جديد.

## 💾 النسخ الاحتياطي المحلي

من داخل التطبيق: الإعدادات ← النسخة الاحتياطية المحلية.

- **تصدير نسخة**: يحمّل ملف ZIP يحتوي على جميع بياناتك وصورك.
- **استيراد نسخة**: يرفع ملف ZIP سبق تصديره، ويستبدل بياناتك الحالية ببيانات النسخة المستوردة.

## ☁️ النسخ الاحتياطي السحابي (S3)

عَمار يدعم أي خدمة تخزين متوافقة مع S3: AWS S3، Cloudflare R2، Backblaze B2، MinIO، Wasabi، DigitalOcean Spaces، وغيرها.

أضف المتغيرات التالية في ملف `.env`:

```
S3_ENDPOINT=https://s3.amazonaws.com
S3_REGION=us-east-1
S3_BUCKET=ammar-backups
S3_ACCESS_KEY=xxxxxxxx
S3_SECRET_KEY=xxxxxxxx
S3_PREFIX=ammar/
S3_FORCE_PATH_STYLE=0
```

> ملاحظة: عند استخدام MinIO أو Cloudflare R2، اضبط `S3_FORCE_PATH_STYLE=1`.

بعد إضافة المتغيرات، أعد تشغيل الحاوية. ثم من داخل التطبيق: الإعدادات ← النسخ الاحتياطي السحابي، يمكنك رفع نسخة فورية، تفعيل النسخ التلقائي اليومي، وضبط سياسة الاحتفاظ.

## 👥 إدارة المستخدمين

الحساب الأول الذي تنشئه هو حساب الأدمن. من الإعدادات ← إدارة المستخدمين (للأدمن فقط) يمكنك:

- فتح/إغلاق التسجيل العام لأي زائر.
- إضافة مستخدمين جدد، تعطيلهم، أو حذفهم.
- إعادة تعيين كلمة مرور أي مستخدم.

كل مستخدم يرى مشاريعه وبياناته فقط، ولا يمكنه الوصول لبيانات مستخدم آخر.

## 🔐 الأمان

المشروع خضع لعدة جولات فحص أمني عميق (راجع [CHANGELOG.md](./CHANGELOG.md) للتفاصيل الكاملة)، وتشمل الحماية:

- توليد تلقائي لسر جلسات آمن (بدون قيم افتراضية معروفة).
- تحقق صارم من ملكية البيانات على كل طلب — عزل كامل بين المستخدمين.
- فحص فعلي لمحتوى الملفات المرفوعة (لا يكتفي بنوع الملف المُعلن).
- حماية من هجمات القوة الغاشمة على تسجيل الدخول والتسجيل.
- تشغيل الحاوية بصلاحيات مستخدم غير-root.

إذا لقيت أي ثغرة أمنية، الرجاء فتح Issue خاص أو التواصل مباشرة بدل نشر التفاصيل علنًا.
